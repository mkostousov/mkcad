### Stability log

- Host runs Hyper-V/VBS → VirtualBox uses NEM (WHv) fallback, not VT-x (VBox.log: "HM: Attempting fall back to NEM").
- 2026-10-10 20:23 and 20:32: guest BSOD 0x0A (IRQL_NOT_LESS_OR_EQUAL) with 8 vCPU + 3D on, Fusion active.
- 20:40: reverted to 4 vCPU, 3D kept on. If BSODs recur → turn 3D off; last resort is disabling host Hyper-V/VBS (user's call).
- After the reboot the guest left mouse button was stuck "down" (GetAsyncKeyState) so injected clicks did nothing; a physical click in the VM window cleared it. Diagnose with `gui.ps1 guest\mouseinfo.ps1` → `C:\mkprobe\out\mouseinfo.txt`.
- Windows OCR returns nothing on large crops dominated by canvas grid; `vmh.py ocr` now falls back to a dark-text threshold (150). Single-letter shortcut columns still need an image look (cheap when cropped).
- Fusion dropdowns toggle: Esc does not reliably close them; `tools/menus.ps1` verifies and retries.
- Keyboard input right after opening a command can be lost (focus/timing); `gui.ps1` tasks may leave a PowerShell window in the foreground. Click the target field, wait ~1 s, then type; verify by reading state.
- 2026-10-12: VM 3D acceleration switched OFF again — required for drawings (AcCoreConsole crashed with 3D on, F236/F238). Fusion uses software rendering now.
- Fusion jobs must be idempotent: a crash loses the open unsaved document.
